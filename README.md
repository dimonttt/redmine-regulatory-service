\# Redmine Regulatory Works Service



Сервис анализирует фактические трудозатраты по сопровождаемым клиентам в Redmine, сравнивает их с плановыми часами за расчётный период, выявляет клиентов с недостаточной выработкой и автоматически подбирает регламентные работы для восполнения недостатка часов. Если типовых работ не хватает — генерирует новые предложения с помощью LLM.



\## Основные возможности



\- \*\*Синхронизация с Redmine\*\*: автоматическое получение проектов (клиентов) и трудозатрат с поддержкой пагинации (забирает все записи, даже если их больше 100). Двусторонняя синхронизация (удаляет записи, удалённые в Redmine).

\- \*\*Расчёт выработки\*\*: сравнение фактических часов с планом, выявление недостатка по настраиваемому порогу.

\- \*\*Умный подбор работ\*\*: подбор типовых регламентных работ из справочника с учётом трудоёмкости и исключением уже выполненных.

\- \*\*LLM-генерация\*\*: если типовых работ не хватает, локальная нейросеть (Qwen) генерирует новые предложения на основе описания клиента, его отрасли и истории работ.

\- \*\*Защита от дублей\*\*: на уровне кода и базы данных (уникальные индексы) при синхронизации и создании задач в Redmine.

\- \*\*Веб-интерфейс\*\*: минималистичная админ-панель на Vue 3 с JWT-авторизацией. Позволяет запускать расчёт, просматривать историю и управлять предложениями (одобрять/отклонять/создавать задачи).

\- \*\*Health-проверки\*\*: эндпоинты `/health/live` и `/health/ready` для мониторинга состояния сервиса.



\## Технологический стек



\- \*\*Backend\*\*: Python 3.12, FastAPI, SQLAlchemy 2.0, Alembic

\- \*\*База данных\*\*: PostgreSQL 16 (в Docker)

\- \*\*Frontend\*\*: Vue 3, Vite, Axios

\- \*\*LLM\*\*: Ollama (локально) + OpenAI-совместимый API

\- \*\*Инфраструктура\*\*: Docker, Docker Compose



\## Запуск проекта



\### Требования

\- Docker Desktop (с WSL 2)

\- Python 3.12+

\- Node.js (для фронтенда)



\### 1. Клонирование и настройка

git clone <URL\_репозитория>

cd redmine-practice



\### 2. Запуск инфраструктуры (Redmine + базы данных)

Проект использует три Docker-контейнера: `redmine`, `redmine\_db` и `app\_db`. Запустите их:

docker compose up -d

Подождите 15–20 секунд и проверьте статус (все три должны быть `Up`):

docker compose ps



\*\*Первичная настройка Redmine (если запускаете первый раз):\*\*

1\. Откройте `http://localhost:3000`. Войдите под `admin` / `admin`.

2\. Смените пароль по требованию системы.

3\. Зайдите в \*\*Администрирование → Настройки → API\*\* и включите \*\*«Включить REST веб-сервис»\*\*. Сохраните.

4\. Зайдите в \*\*Мой аккаунт\*\*, скопируйте \*\*«Ключ доступа к API»\*\* (понадобится для `.env`).



\### 3. Настройка бэкенда (Python)

Создайте виртуальное окружение и установите зависимости:

python -m venv .venv

.venv\\Scripts\\Activate.ps1

pip install -r requirements.txt



Создайте файл `.env` на основе `.env.example` и заполните его (ключ Redmine, секретный ключ для JWT, параметры БД).



Примените миграции базы данных:

alembic upgrade head



Запустите сервер:

uvicorn app.main:app --reload

Бэкенд доступен на `http://127.0.0.1:8000`. Документация (Swagger): `http://127.0.0.1:8000/docs`.



\### 4. Настройка LLM (Ollama)

Установите \[Ollama](https://ollama.com/) и скачайте модель:

ollama pull qwen2.5:7b

Убедитесь, что Ollama запущена в фоне. В `.env` укажите `LLM\_BASE\_URL=http://127.0.0.1:11434/v1`.



\### 5. Наполнение базы демо-данными

python -m scripts.seed\_plans

python -m scripts.seed\_regulatory\_works

python -m scripts.update\_clients\_info



\### 6. Настройка фронтенда (Vue)

Перейдите в папку `frontend` и установите зависимости:

cd frontend

npm install

npm run dev

Интерфейс доступен на `http://localhost:5173`.

\## Основные эндпоинты API



\- `POST /api/runs` — запустить полный расчёт за указанный месяц.

\- `GET /api/runs` — получить историю запусков.

\- `GET /api/suggestions?run\_id={id}` — получить предложения по конкретному запуску.

\- `POST /api/suggestions/{id}/approve` — одобрить предложение.

\- `POST /api/suggestions/{id}/reject` — отклонить предложение.

\- `POST /api/suggestions/{id}/create-task` — создать задачу в Redmine по предложению (с защитой от дублей).

\- `GET /health/live` — проверка живости.

\- `GET /health/ready` — проверка готовности (БД, Redmine, LLM).
